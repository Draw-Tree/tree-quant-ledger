# 計分窗口規範（永久口徑）

維護者裁定 2026-08-02：**全部讀數一律「星期一開市價 → 星期五收市價」，
逐週向前滾動。任何新增的讀數必須沿用本口徑，不得自行定義。**

## 定義

```
起點 ＝ 名單日之後第一個交易日的開市價
終點 ＝ 窗口末端最後一個交易日的收市價
```

名單於**星期日 16:00 HKT** 公佈，故第一個交易日通常是星期一、窗口末端
最後一個交易日通常是星期五。第 N 週讀數＝由**同一個起點**量到第 N 個
星期五的收市——各週為巢狀窗口而非獨立區段，故一路滾落去覆蓋名單公佈
之後的全部時間，中間不留空隙。

事前一週（「訊號前一週」）＝把名單日退七日，套同一個定義。它與上一週的
計分讀數逐位相同——同一段時間在兩處必然同一個數字。

全池中位必須以同一口徑、同一份名單日計出。分母不同、窗口不同，超額數字
兩頭就對不上。

唯一實作：`_lib/scoring_window.py`。任何渲染器都必須呼叫它，不得自行由
價格檔案相減。

## 為何寫死這一條

2026-08-02 之前，同一個實驗有三個口徑並存，同一份名單的同一檔股票報出
三個數：

| 檔（2026-07-26 名單） | 一開→五收 | 五收→五收 | 週一約十點報價 |
|---|---|---|---|
| AMD | −9.74% | −8.77% | −0.32% |
| PLTR | −2.45% | +0.11% | −2.80% |
| ISRG | +2.71% | +4.69% | −0.80% |

PLTR 連正負號都不同。全池中位亦分別是 −0.37%／+1.06%／+2.90%，池的
組成更是 78／73／68 檔各不相同——換言之兩個視圖的「超額」根本沒有可比性。

三者的毛病各異：

* **五收 → 五收**：起點在名單公佈之前就已經定格，讀者不可能在該價入場，
  等於把星期一的跳空算進訊號帳上。
* **週一約十點報價**：取價函數是 `range=5d&interval=1d` 取最後一根日線的
  close，盤中執行時即當刻成交價。幾點取到，取決於 workflow 跑得多快——
  不是一個有定義的市場事件。ISRG 那天由開市 344.00 升到收市 356.83，
  該函數取到 356.18，等於在接近全日高位入場，把 +2.71% 讀成 −0.80%。
* **一開 → 五收**：名單星期日出，星期一開市是最早可行動的時刻。

## 不受本規範管轄者

執行層（Sleeve A／B／C）量的是**真實成交**，用實際成交價才對。兩者本
就是不同的問題——「訊號有沒有預測力」與「我們實際賺蝕多少」——但報告
中必須標明哪個讀數是哪一層，不可混為一談。

**執行層向本口徑對齊（2026-08-04）**：股票腿改用 MOO（`MKT` + `tif=OPG`），
成交於開市競價，即與本規範的入場價同一個市場事件。此前執行層在開市後
15 分鐘落可成交限價單，理論與實際之間恆常隔著開頭那一段走勢——那個差
不是任何一方算錯，但它把「滑價與手續費有多少」這個真正想量的東西淹沒了。
對齊之後，兩組數字的差別只剩滑價、手續費、與被剔除不建倉的檔。

代價：MOO 沒有價格保護，開市競價跳空多少就成交在多少，薄股尤甚。維護者
2026-08-04 裁定接受——模擬帳戶量的是訊號有沒有預測力，不是執行優化。

盤中臨時單腿平倉（判定翻轉即出場）不轉 MOO：那條路徑要即時成交，OPG
會令它等到翌日開市，等於靜默改變了出場時點。

## 已知假設

以官方開市價入場，隱含假設是可在開市競價成交。較保守的替代是以星期一
收市價入場，但那等於白白放棄第一日的走勢而不明言。維護者 2026-08-02
裁定採用開市價。
