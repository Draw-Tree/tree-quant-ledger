# 🔭 H-lead：我們是否真的早過市場？

> 本系統的核心主張：AI 搜索令判定改變**早於**市場傳播，時間差是
> alpha 的來源。本檔把這句話變成可證偽假說——逐訊號量度三個時間戳，
> 逐週公開讀數，判準先寫後量、不得事後移動。

## 量甚麼

| 時間戳 | 定義 |
|---|---|
| `t_us` | 我方判定改變日（驅動證據獲裁定之日） |
| `t_media` | 主流媒體首篇報道日（判定日前 30 日起重搜的傳播時間線） |
| `t_x` | X（Twitter）首帖／首條高互動帖（like ≥100 或 repost ≥20） |
| `t_price` | 股價消化日（日回報 \|z\|≥2 首日，±5 個交易日窗） |

**lead ＝ 對方時間戳 − t_us**：正數＝我們早，負數＝我們遲。
量度於每週對答案時（T+7）執行——搜尋引擎索引有滯後，回顧才有全貌；
首掃即凍結，重掃須明示 force 並在 commit 歷史留痕。

## 預登記假說與判準（CALIBRATION_SPEC §v3.13，先寫後量）

- **主假說**：`lead_media > 0`（領先組）之訊號，+1 週超額優於
  `lead_media ≤ 0`（落後組）。
- **首檢（n ≥ 20）**：領先組超額中位數與方向命中率**同時**高於落後組
  ——描述性檢視，不作規則改動。
- **正式檢定（n ≥ 40）**：兩組超額之 permutation 檢定（單尾，α=0.05）。
- **若不成立**：「資訊速度」敘事須修正——alpha 來源可能在判定紀律
  而非速度。這是重要發現，不是失敗。

## 量度偏差（先此揭示，讀數須以此為前提）

1. **lead 屬上界估計**：檢索非窮盡（相關性排序、上限 20 篇），搜漏
   更早的報道只會令我方顯得更早。兩組同受此偏差，組間比較仍成立，
   絕對數值不可按字面讀。
2. 文章 `published_date` 屬爬蟲後設資料，可能反映改版日而非首發日。
3. X 只覆蓋最近 7 日（recent search）——量到訊號**之後**的傳播，
   量不到之前已在 X 流傳。
4. **財報訊號（📅）定義上難以領先媒體**：財報是廣播事件。分層解讀
   屬 2026-08-04 見首批數據後的 post-hoc 觀察，如實標明，不改判準。
5. freshness 核數為 tri-state：走漏**候選**須人手覆核方作數；
   「無裁定可核」與「核過乾淨」是兩回事，分開呈報。

## 讀數如何驅動自我升級

- 走漏候選確認率持續偏高 ⇒ 反向搜索深度不足，換／加 data source
  有量化依據；
- 某類驅動來源恆常領先而主流恆常滯後 ⇒ 該層來源加權有數撐；
- `lead_price ≤ 0` 是「已定價」的直接證據，補足事前走勢 gate；
- 假說不成立 ⇒ edge 敘事修正，資源移往判定紀律而非搜索速度。
